# 중앙 두 선로·우측통행·경계 진입과 1분 정차

- 작성일/최종 갱신: 2026-11-12
- 상태: 완료
- 관련 작업 기록: [#7 중앙 선로·경계 진입·정차](../work/%237%20central-tracks-boundary-dwell.md)

## 배경과 목표

사용자는 열차를 가운데 직선 두 선로에만 배치하고 앱에서 우측통행하도록 변경했다. 열차는 지도의 경계에서 차체가 조금씩 드러나며 진입해 역에서 약 60초 대기한 뒤 반대 경계로 차체 전체가 빠져나가야 한다.

## 확인된 사실과 결정

기존 중앙 본선은 way/545488739와 way/971722969이며 양옆 siding과 구분된다. 기존 코드는 OSM 철도 방향을 따랐고 수동 데모는 맵 안에서 시작했다. 사용자 확정(2026-11-12)에 따라 중앙 동쪽 선로를 강릉 방면, 중앙 서쪽 선로를 서울 방면으로 사용한다. 이는 앱 표현용 우측통행이며 OSM 원본/실제 철도 운행 규칙을 바꾸지 않는다. 도로 통행 코드는 변경하지 않는다.

## 범위와 완료 조건

1. 중앙 본선 두 개를 연결해 방향별 오른쪽으로 운행. 실제 장면 행렬에서도 진행 방향의 우측임을 검증한다.
2. GLB 길이를 고려해 시작·끝의 차체 전체를 ±249m 경계 바깥에 둔다. 기존 전역 클리핑과 같은 경계를 사용해 입·출구에서 차체가 점진적으로 보이거나 사라지게 한다.
3. 접근→감속→60초 정차→가속→퇴장 상태를 시간 기반으로 계산한다. 자동 편은 시간표의 진부 기준 시각에 정차를 시작하고 수동 데모도 같은 과정을 따른다. 정차 60초는 실제 운행자료가 아니라 사용자 지정 연출이다.
4. 일시정지/재개·중복 방지·요일·한국 시각·시간표 검토기한·기존 이동 포털을 유지한다. 새 동작의 단위 및 브라우저 검사를 실행하고 문서/인덱스/BRAIN을 갱신한다.

## 미결 사항과 위험

실제 열차의 차종·지연·승강장 배정·정차 시간은 검증되지 않았다. 새 우측통행 연출은 원본 OSM 철도 방향과 반대다. 경계에서 부분 렌더링을 확인할 때 단순 객체 visible 값만으로 성공을 판단하지 않고 실제 화면도 확인한다.

## 변경 및 결과

2026-11-12: 중앙 본선 우측통행, 전체 차체 길이를 고려한 경계 진입/퇴장, 감속·60초 정차·가속, 수동/자동 공통 과정을 구현했다. 빌드·단위 15개·새 렌더링 13개·기존 포털/열차 19개·기존 지도 29개 및 문서 검사가 통과했다. 원본 철도/시간표 자료는 유지하고 새로운 통행·정차는 앱 연출로 명시했다.
