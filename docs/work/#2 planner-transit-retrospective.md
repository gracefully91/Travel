# AI 없는 일정 계산과 대중교통 DB 회고

- 작업 번호: #2
- 날짜: 2026-11-12
- 상태: 완료
- 관련 계획: 기존 대화 기반 회고

## 기록 성격

2026-11-12에 기존 구현과 PLANNER.md, TRANSIT_DB.md, 검사 산출물을 대조한 회고다.

## 요청과 결정

숙소·여행지·여행 일수·날짜별 지정 또는 자동 배분을 입력해 영업시간과 교통편을 반영한다. AI 모델은 사용하지 않는다. 외부 요청을 줄이도록 실제 확보한 교통 자료를 저장한다.

## 변경 내용

- src/planner/: 일정 입력·분배·영업시간·체류·이동·복귀 제한을 계산하는 결정적 엔진과 UI. 수동 날짜 배정과 전체 기간 자동 배분을 지원한다.
- server/planner-api.ts: 공개 OSM/OSRM/FOSSGIS 경로, 장소 검색, 서버 측 TAGO 연결. 택시는 거리 요율 기반 참고값이며 실시간 정체는 미반영.
- server/transit-store.ts, data/runtime/transit.sqlite, scripts/transit-db.mjs: 노선·정류장·운행일별 시각과 API 영구 캐시. API 키는 문서나 DB에 기록하지 않는다.
- BIS 원본은 data/raw/planner/bus-224-map.json 등. 당시 3개 노선, 49개 정류장 중 승차 가능 47개를 확보했다.

## 검증

기존 artifacts/planner-test-report.json의 브라우저 검사 17개와 오류 0개, planner-api-report.json의 검사 5개를 확인했다. 원본 조회와 테스트 상세는 ../../PLANNER.md 및 ../../TRANSIT_DB.md에 있다. 이 회고에서 과거 단위 테스트를 새로 돌렸다고 주장하지 않는다.

## 한계와 재개 지점

확정 버스 운행편은 확보하지 못했다. 평균 통과 예상시각을 확정 운행표로 바꾸지 않는다. TAGO 인증키 미설정 상태이며 캐시가 없는 실시간 제공자 연결은 이용할 수 없다. 정적 배포만으로 Node API/SQLite를 서비스할 수 없으므로 배포 시 서버/영구 저장이 필요하다.

## 문서 반영

- 작업 인덱스: 반영
- 관련 계획: 해당 없음 — 기존 대화와 실제 구현을 회고
- BRAIN: 현재 구현과 제한으로 요약 반영
