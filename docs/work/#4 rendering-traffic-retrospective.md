## 기록 성격

2026-11-12에 이 대화에서 실제 수행한 버그 수정과 코드/보고서로 작성했다. 과거에 잘못 넣은 보정을 숨기거나 현재 결론에 맞춰 과거 작업을 지우지 않는다.

## 원인과 수정 순서

1. 사용자가 길에 줄무늬가 생겼다 사라진다고 보고했다. 정지 카메라·화면 크기는 일정했고, 바닥 상자와 5mm 위 평면이 중복됐다. DioramaBase로 면을 하나로 만들고 near를 0.2→2m로 높였으며 얇은 부지 면의 그림자를 정리했다. 자동 카메라 갱신도 중복되지 않게 정렬했다.
2. 사용자가 차량이 모두 좌측통행처럼 보인다고 보고했다. 데이터의 X=동쪽/+Z=북쪽을 Y-up Three.js에 그대로 표시하면 북쪽을 위로 봤을 때 좌우가 반전됐다. geographic-frame에서 Z를 한 번 반전하고 카메라/나침반/간판을 맞췄다. 데이터 축은 보존했다.
3. 앞선 역주행 보고에 대응해 역 앞 7개 way를 원본 OSM과 반대로 강제했던 보정이 남아 있었다. 좌표계 수정 후 사용자가 보정 자체의 역전을 확인해 제거했다. 현재는 OSM oneway/노드 순서를 차량·화살표가 함께 따른다. data/processed/traffic-corrections.json에는 제거 이력을 보존하고 실행 코드에서는 읽지 않는다.

## 검증과 실패에서 배운 점

- 빌드 통과. 기존 artifacts/jitter-report.json의 7개 검사: 정지 카메라·화면 높이, 회전 관성 정착, 정확한 복귀, 정지 픽셀 동일성 등.
- artifacts/traffic-handedness-report.json: 실제 장면 행렬을 거친 북쪽/동쪽 투영과 진행 벡터×위쪽 벡터로 계산한 우측 차선, 차량 전방/실제 이동 일치. 당시 양방향 도로 12개 구간에서 우측임을 확인했다.
- 별도 반전 제거 후 npm test 29개 통과: 역 앞 북동쪽 진행, 경로 연결, 우측 차선, 카메라/장소/모바일, 콘솔 오류 없음.
- 이전 검사는 데이터 좌표만 확인해 화면 반전을 놓쳤다. 이후 렌더링 좌표까지 검사하도록 보강했다. 카메라 검사에서 비동기 predicate가 실제 정착 대기를 보장하지 않아 동기 predicate로 수정했다.
