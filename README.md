# Pyeongchang in Miniature

진부(오대산)역의 실제 OpenStreetMap 지리 정보와 제공된 GLB를 사용하는 React + TypeScript + React Three Fiber MVP입니다. 3D 지도에는 API 키와 서버 DB가 필요하지 않습니다. 새 여행 일정 기능의 공공 열차 조회에는 별도 인증키가 필요합니다. 지도 원본을 저장했으므로 실행 시 지도 API에 다시 접속하지 않습니다. 외부 글꼴 서버에 의존하지 않고 시스템 글꼴로 표시합니다.

숙소·여행 기간·방문 장소로 일정을 만드는 기능을 추가했습니다. [일정 만들기 사용법과 데이터 연결 상태](PLANNER.md)를 참고하세요.

첫 화면에서 진부권·횡계 시내권·리조트권을 고르고 작은 3D 맵으로 들어갈 수 있습니다. [구역 지도·소형 맵·전환 사용법](MAPS.md)을 참고하세요.

## 실행

Node.js 22.18 이상을 사용합니다. 이 작업은 Node.js 24.14.1에서 확인했습니다.

```powershell
cd C:\dev\@Travel
npm install
npm run dev
```

브라우저: **http://localhost:5173/**

## 공개 미리보기

GitHub Pages: **https://gracefully91.github.io/Travel/** · [공개 저장소](https://github.com/gracefully91/Travel)

공개판은 저장소 안의 정적 데이터만 읽어 3D 지도를 표시하고 런타임에 외부 API를 호출하지 않습니다. 일정 계산은 저장된 6개 기본 장소 간 2026-11-11 OSM 경로 snapshot 범위로 제한됩니다. 임의 장소 검색과 조회형 열차 API는 제공하지 않으며 실시간 정체·버스 위치도 없습니다. 현재 BIS 시간표 중 게시일이 2025-12-30인 자료는 자동 일정에서 제외했습니다.

공식 교통 원본과 공개 정적 snapshot을 갱신하려면 네트워크가 연결된 개발 환경에서 실행합니다.

```powershell
npm run data:transit:fetch
npm run build
git add data/raw/transit-updates public/data/transport-snapshot.json
git commit -m "Refresh public transport snapshot"
git push
```

같은 네트워크의 휴대폰은 Vite가 출력하는 Network 주소로 접속할 수 있습니다. 방화벽 허용 여부는 환경에 따라 다릅니다.

```powershell
npm run build
npm run preview
```

프로덕션 빌드는 `dist/`, preview 기본 주소는 http://localhost:4173/ 입니다.

## 실제 좌표와 데이터

취득 날짜: **2026-11-11 (한국 시간)**.

기준 원점은 OSM 역사 건물 `way/545414817`의 면적 중심 **37.642732793, 128.574456369**입니다. OSM 역 시설 노드 `10591459522`의 좌표 **37.6425685, 128.5748224**와는 기준 대상이 다릅니다. 앱은 건물 중심을 원점으로 사용합니다. 건물 외곽선에서 계산한 장축 길이는 약 **71.23m**, 폭은 **27.93m**, 동쪽에서 북쪽으로 향하는 장축 각도는 **53.550°**입니다. 이는 OSM 형상에서 계산한 값이며 실측 치수는 아닙니다.

`src/lib/geo.ts`는 구면 지구의 로컬 equirectangular 투영을 사용합니다. 기준 위도의 cos 보정으로 X는 동쪽, Y는 높이, Z는 북쪽이며 단위는 미터입니다. 이 수백 미터 영역을 위한 근사 투영이며 측량용 좌표계가 아닙니다. 동일한 변환을 모든 지형 요소에 적용합니다.

원본 지도 API에서 약 700m 크기의 경계 상자를 받아 건물·도로·보행로·철도·승강장·주차장·산림 영역을 추출했습니다. API가 반환하는 way는 경계 바깥으로도 이어질 수 있습니다. 화면에서는 중심에서 동서남북 약 249m를 기준으로 잘라서 표시합니다. 초기 초점은 역과 약 100m 범위의 전면 보행 공간이며 전체 보기에서는 주변 맥락을 확인할 수 있습니다.

출처:

- [OSM 역사 건물 외곽선](https://www.openstreetmap.org/way/545414817)
- [OSM 역 시설 노드](https://www.openstreetmap.org/node/10591459522)
- [원본 OSM map API 요청](https://www.openstreetmap.org/api/0.6/map?bbox=128.5705,37.6396,128.5784,37.6459)
- [OSM 저작권 및 ODbL 안내](https://www.openstreetmap.org/copyright)
- [코레일 공개 KTX 자료](https://www.letskorail.com/etc/pyeongChang/eng_timetable.pdf): 진부역의 KTX 노선 관계 확인용. 현재 열차 시간표로 사용하지 않습니다.
- [진부역 주소 확인](https://train.asamaru.net/열차역/진부-오대산-역/)

Overpass POST 요청에서 406/429가 발생해 공식 OSM 지도 API로 전환했습니다. 이후 Overpass GET도 응답했지만, 최종 정규화 데이터의 기준은 보존한 공식 API XML입니다. `data/raw/jinbu-osm.xml`은 원본, `jinbu-osm.json`은 XML 요소를 JSON으로 옮긴 스냅샷입니다. 관계는 원본 XML에 보존되지만 이번 장면은 직접 geometry가 있는 way와 node를 사용합니다.

저장된 스냅샷으로 앱을 바로 실행할 수 있습니다. 갱신은 선택 사항입니다.

```powershell
npm run data:fetch
```

공식 API를 우선 사용하고 실패 시 Overpass GET을 시도합니다. 기존 XML을 다시 처리하려면 `npm run data:process`를 사용합니다. 이 두 데이터 작업에는 Python 3가 필요합니다. 앱 빌드와 실행에는 Python이 필요하지 않습니다.

| 여행 지점 | OSM 보행로 548366613 위에 정한 **앱 데모 지점**. 측량한 출입구나 별도 관광 장소 아님 |

## GLB 분석과 보정

`public/models/jinbu-station.glb`를 실제 GLTFLoader로 로드합니다. 파일 크기 **986,076 bytes**, Meshy glTF 2.0, 메시 1개, POSITION 정점 27,372개, 인덱스 164,208개(삼각형 54,736개)입니다. 원본에는 재질·텍스처·UV·법선이 없으며 코드에서 법선을 계산합니다. 노드 변환은 항등 행렬입니다.

원본 바운딩 박스:

```text
min (-0.950655, -0.168504, -0.325853)
max ( 0.947848,  0.171162,  0.321052)
size (1.898503, 0.339666, 0.646905)
```

긴 축 X, 높이 Y, 깊이 Z로 해석합니다. 바닥을 Y=0에 맞추고 중심을 원점으로 이동한 뒤 OSM 장축·폭에 맞춥니다. Y 스케일은 장축 X 스케일을 따라 약 12.74m 높이가 됩니다. 이는 실제 역사 높이 확인값이 아닙니다.

`src/components/StationModel.tsx`의 `stationAlignment`에서 회전·오프셋·높이 배율·숨길 메시 이름을 조정할 수 있습니다. 현재 회전 Y는 약 -0.934628 rad입니다. OSM 외곽선의 장축 정렬은 확인했으나 GLB 내부 정면과 실제 출입구 방향의 세부 일치까지 측량 검증한 것은 아닙니다.

전체 메시는 은회색 재질로 유지하고 별도 유리창·멀리언·3D 역명 표지판을 얇게 보완합니다. 첨부 이미지는 외관 참고이며 원본 텍스처로 투사하지 않았습니다. 곡면 지붕·기둥·캐노피 등 원본 메시를 사용합니다. 원본 GLB는 수정하지 않습니다. 단일 메시이므로 특정 지붕·벽·기둥에 정밀한 개별 재질을 입히는 데 한계가 있습니다.

GLB가 없거나 로드되지 않으면 임시 코드 건물과 상태 문구가 표시됩니다. 동일 경로에 파일을 추가하고 페이지를 새로고침하면 GLB로 대체됩니다. 추후 Draco/Meshopt를 사용하면 StationModel의 로더에 디코더 설정을 추가할 수 있습니다.

## 역 앞 통행 방향 복원 (2026-11-12)

지도 표시의 좌우 반전을 수정한 뒤, 사용자가 역 앞의 별도 반전 보정 때문에 방향이 뒤집혔다고 확인했습니다. 진입·순환로 7개 way에 적용했던 반전을 제거했습니다. 차량 경로와 일방통행 화살표는 저장된 OSM oneway 및 노드 순서를 따릅니다. data/processed/traffic-corrections.json에는 제거 이력만 남기며 실행 코드에서는 읽지 않습니다.

회귀 검사는 역 앞 5개 평행 통행로의 원본 진행 방향(북동쪽), 7개 보정 대상의 OSM 방향 복원, 실제 차량의 전진 방향, 경로 연결 및 렌더링 우측 차선을 확인합니다. 차량 전방은 흰색, 후방은 빨간색 램프입니다.

대중교통 DB와 열차 조회 결과 영구 캐시를 추가했습니다. [저장·갱신·운행표 가져오기·지도 성능 범위](TRANSIT_DB.md)를 참고하세요. Node.js 22.18 이상(권장 24.14 이상)이 필요합니다.

## 표면 깜빡임 보정 (2026-11-12)

바닥 상자 위 5mm/10mm 간격의 중복 평면을 제거하고, 카메라 near를 0.2m에서 2m로 조정해 깊이 정밀도를 높였습니다. 녹지·철도 부지·주차장 표면 높이를 구분하고 얇은 부지 면의 그림자 투사를 껐습니다. 이는 표시용 표면 구분이며 실제 지형 고도를 뜻하지 않습니다. 카메라 자동 이동은 OrbitControls보다 먼저 계산하며 controls 갱신을 중복 실행하지 않습니다.

회귀 검사: npm run test:jitter. Headless Edge 소프트웨어 WebGL 기준입니다.

## 지도 좌우 반전 보정 (2026-11-12)

데이터 좌표는 X=동쪽, Z=북쪽으로 보존합니다. Y-up인 Three.js 화면에서는 북쪽을 -Z로 표시하도록 geographic-frame에서 Z를 반전합니다. 기존에는 데이터를 그대로 표시해 북쪽을 위로 볼 때 동쪽이 화면 왼쪽에 나타났으며, 데이터상 우측 차선도 화면상 좌측으로 보였습니다. 역·마을 맵, 카메라 목적지, 나침반, 간판을 함께 보정했습니다. 역 앞에 별도로 넣었던 일방통행 반전도 이후 제거하여 원본 OSM 방향으로 복원했습니다.

검사: node tests/traffic-handedness.mjs. 실제 장면의 월드 행렬을 적용한 북쪽/동쪽 화면 투영, 진행 벡터와 위쪽 벡터의 외적으로 계산한 우측 차선, 차량 앞면과 실제 이동 방향을 검사합니다. 기존 검사는 데이터 좌표만 확인했기 때문에 표시 단계의 반전을 놓쳤습니다.

## 도로 표지로 맵 연결 · 시간표 KTX (2026-11-12)
